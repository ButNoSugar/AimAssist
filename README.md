# AimAssist

Продвинутый триггербот с автонаведением для **одиночного мира Minecraft** —
курсор следует за изменениями на экране (частицы разрушенного блока и т.п.).
Сделан для записи видео про контроль аима, не для мультиплеера.

Только Windows: прозрачный оверлей и относительный ввод мыши опираются на
WinAPI. На другой ОС скрипт сразу скажет, что именно завязано на Windows,
и не станет запускаться.

## Тестовая версия (`test`)

Ветка `test` предназначена для проверки изменений перед отдельным решением
о слиянии в `main`. Наличие ветки не делает её приватной: доступ наследуется
от репозитория. Рекомендуется **Python 3.12**.

После установки зависимостей двойной клик по `run.bat` открывает панель
управления. Консольный режим: `run.bat --console`.

1. Выберите окно Minecraft в панели, затем вернитесь в игру.
2. Оставьте «Только наблюдать» включённым, держите Ctrl или Alt и проверьте
   предпросмотр: слева исходный кадр с рамками, справа маска изменений.
3. Настройте чувствительность, размер пятна и подтверждение цели. Вкладка
   «Дополнительно» содержит остальные настройки и маски исключения.
4. Чтобы разрешить мышь, снимите «Только наблюдать» и нажмите «Применить
   настройки». Автоклик включается отдельно. При потере активного окна игры
   действия приостанавливаются. Каждый запуск и загрузка профиля снова
   включает наблюдение.
5. F8 всегда завершает работу и никогда не удаляет записи. Кнопки паузы и
   продолжения в панели действуют отдельно.

Детектор учитывает близость к прицелу, ограничивает размер/форму пятен,
подтверждает кандидата несколькими наблюдениями и удерживает выбранную цель.
Это фильтрация изменений изображения, а не распознавание объектов Minecraft:
качество нужно проверить на ваших сценах. Для коротких частиц сравните
`confirm_frames=1` и `2`, учитывая пропуски и ложные срабатывания.

Маски задаются в долях клиентской области игры: например
`exclusion_rects=[[0.6,0.6,1,1]]` исключает правый нижний участок с рукой.
`ignore_bottom_fraction=0.15` исключает нижние 15% окна. По умолчанию маски
пусты, чтобы не скрыть нужные частицы без проверки. Экспериментальная
`compensate_camera` оценивает только общий перенос, не перспективу и параллакс;
по умолчанию выключена.

### Запись и повтор без игры

Первое нажатие F9 включает запись, если она ещё выключена; следующее сохраняет
последние пары кадров в `tune/<время>/`. Запись также включается настройкой
`tune_mode`. Сохраняются точные исходные массивы, маска, параметры детекции,
выбранная цель и причина разрешения/пропуска ввода, включая отрицательные
решения. Файлы остаются локальными и в Git не добавляются. Буфер ограничен
`tune_frames` и 256 МиБ; запись может увеличить задержку.

```bat
.venv\Scripts\python aim_recording.py tune\<папка-записи>
.venv\Scripts\python aim_recording.py tune\<папка-записи> --threshold 45
```

Повтор пересчитывает детектор на тех же исходных кадрах и печатает JSON.
Он не захватывает экран и не управляет мышью. Это инструмент сравнения
фильтров; число найденных пятен само по себе не является метрикой точности.

### Проверки

```bat
.venv\Scripts\python tests/run.py
```

На Linux для тестов достаточно NumPy и `opencv-python-headless`; Windows и GUI
подменяются только внутри старых интеграционных наборов. Новые модули
детекции, записи, модели панели и обмена процессами проверяются отдельно.
Проверка через заглушки не заменяет ручной запуск на Windows.

Перед использованием проверьте на Windows: выбор окна и Alt+Tab, Ctrl/Alt,
F8, режим наблюдения, маски, автоклик возле прицела, сохранение/повтор записи,
профили и масштабирование экрана. Сравните одинаковые сцены с прежней версией:
вода, частицы, рука, поворот камеры, открытие инвентаря и потеря цели.

## Установка

Первый раз — создать окружение и поставить модули:

```bat
py -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

Дальше — двойной клик по **`run.bat`** (панель управления). Он сам находит `.venv` рядом со
скриптом и не закрывает окно после выхода, так что ошибку видно.

IDE не нужна. Если запустить `python aim_tracker.py` интерпретатором без
модулей, скрипт сам найдёт `.venv` и перезапустится через него. Когда venv
лежит в другом месте, путь к его питону можно задать переменной среды:

```bat
set AIMTRACKER_PYTHON=C:\путь\к\venv\Scripts\python.exe
```

## Управление

| | |
|---|---|
| **Ctrl** (держать) | слежение в области вокруг прицела |
| **Alt** (держать) | слежение по всему окну игры / экрану |
| **F6** | автоклик вкл/выкл |
| **F7** | рамка оверлея вкл/выкл (выключенная = быстрый режим) |
| **F8** | аварийная остановка |

В игре курсор по экрану не ездит, поэтому старый аварийный тормоз
«увести курсор в угол» там не работает — для этого и нужна F8.

## Что видно при работе

Пока держишь клавишу слежения, внизу живёт одна строка, обновляемая на месте:

```
[Ctrl] цель (781,469)  area 24px  пятен 2 lock  4.1 мс  SendInput
```

Отпускаешь клавишу — строка пропадает и возвращается приглашение `>`.
Подробный лог по каждой детекции выключен (на 200 Гц он заливает консоль);
включается командой `set debug_log on`, когда нужно отлаживать.

## Консоль

Скрипт принимает команды, пока работает:

| команда | что делает |
|---|---|
| `help` | команды и все настройки на одной странице |
| `help <имя>` | разбор одной настройки целиком |
| `set <имя> <значение>` | изменить настройку |
| `window` | к какому окну привязан прицел и как двигается мышь |
| `profile` | профили настроек: список и управление |
| `bench` | замерить скорость захвата и детекции |
| `reset_config` | стереть файл конфига |

Каждая команда открывает свою страницу и очищает экран, так что на нём всегда
только то, что ты открыл. Если что-то непонятно — `help <имя>` разбирает
настройку целиком: что она делает, как подбирать, чем грозят крайние значения.
Описание есть у каждой настройки.

Задержка в живой строке красится по бюджету кадра: зелёная — с запасом,
жёлтая — ещё успеваем, красная — в кадр не уложились (при 60 Гц это 16.6 мс).
Цвет отключается через `set color off`, частота перерисовки — `set status_hz`
(0 совсем выключает живую строку и запись в консоль во время слежения).

Настройки хранятся в `aim_config.json` рядом со скриптом, профилями — под
разные сцены. Файл создаётся при первом запуске; `reset_config` стирает его.

## Настройка под сцену

`set tune_mode on` включает запись исходных пар кадров, а F9 сохраняет буфер.
На предпросмотре зелёная рамка обозначает подтверждённую цель, жёлтая —
остальные кандидаты, серая — отсеянные пятна. Точная причина решения видна
в панели и сохраняется в метаданных записи. F8 всегда завершает программу;
пауза и продолжение не удаляют файлы. Подробнее — раздел записи выше.

## Если в игре не наводится

1. `window pick` — выбрать окно игры из списка открытых. Запоминается имя exe,
   потому что заголовок переписывают лаунчеры и моды. `window` покажет, к чему
   привязались и когда это окно видели в последний раз.
2. В логе детекции должно быть `SendInput dx=.. dy=..` с ненулевыми числами.
   Нули — проблема в детекции или прицеле, а не во вводе.
3. Камеру перебрасывает через цель — `set camera_gain 0.3`; доворачивает
   слишком вяло — больше `0.5`.
4. Персонаж крутится без остановки — скрипт читает собственный разворот.
   Увеличь `settle_after_action`, проверь `global_motion_limit`.
5. Автоклик бьёт по воздуху без остановки — подними `click_tolerance`, чтобы
   бить только по наведённой цели.
6. Клавиша слежения конфликтует с игровым биндом (по умолчанию Ctrl, а это
   часто присед) — `set track_key mouse4` или любая свободная клавиша.
