# AimAssist

Продвинутый триггербот с автонаведением для **одиночного мира Minecraft** —
курсор следует за изменениями на экране (частицы разрушенного блока и т.п.).
Сделан для записи видео про контроль аима, не для мультиплеера.

Только Windows: прозрачный оверлей и относительный ввод мыши опираются на
WinAPI. На другой ОС скрипт сразу скажет, что именно завязано на Windows,
и не станет запускаться.

## Запуск

Первый раз — создать окружение и поставить модули:

```bat
py -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

Дальше — двойной клик по **`run.bat`**. Он сам находит `.venv` рядом со
скриптом и не закрывает окно после выхода, так что ошибку видно.

IDE не нужна. Если запустить `python aim_tracker.py` интерпретатором без
модулей, скрипт сам найдёт `.venv` и перезапустится через него. Когда venv
лежит в другом месте, путь к его питону можно задать переменной среды:

```bat
set AIMTRACKER_PYTHON=C:\путь\к\venv\Scripts\python.exe
```

## Управление

| | |
|---|---|
| **Ctrl** (держать) | слежение в области вокруг прицела |
| **Alt** (держать) | слежение по всему окну игры / экрану |
| **F6** | автоклик вкл/выкл |
| **F7** | рамка оверлея вкл/выкл (выключенная = быстрый режим) |
| **F8** | аварийная остановка |

В игре курсор по экрану не ездит, поэтому старый аварийный тормоз
«увести курсор в угол» там не работает — для этого и нужна F8.

## Что видно при работе

Пока держишь клавишу слежения, внизу живёт одна строка, обновляемая на месте:

```
[Ctrl] цель (781,469)  area 24px  пятен 2 lock  4.1 мс  SendInput
```

Отпускаешь клавишу — строка пропадает и возвращается приглашение `>`.
Подробный лог по каждой детекции выключен (на 200 Гц он заливает консоль);
включается командой `log on`, когда нужно отлаживать.

## Консоль

Скрипт принимает команды, пока работает:

| команда | что делает |
|---|---|
| `help` | команды и все настройки на одной странице |
| `help <имя>` | разбор одной настройки целиком |
| `set <имя> <значение>` | изменить настройку |
| `window` | к какому окну привязан прицел и как двигается мышь |
| `profile` | профили настроек: список и управление |
| `bench` | замерить скорость захвата и детекции |
| `reset_config` | стереть файл конфига |

Каждая команда открывает свою страницу и очищает экран, так что на нём всегда
только то, что ты открыл. Если что-то непонятно — `help <имя>` разбирает
настройку целиком: что она делает, как подбирать, чем грозят крайние значения.
Описание есть у каждой настройки.

Задержка в живой строке красится по бюджету кадра: зелёная — с запасом,
жёлтая — ещё успеваем, красная — в кадр не уложились (при 60 Гц это 16.6 мс).
Цвет отключается через `set color off`, частота перерисовки — `set status_hz`
(0 совсем выключает живую строку и запись в консоль во время слежения).

Настройки хранятся в `aim_config.json` рядом со скриптом, профилями — под
разные сцены. Файл создаётся при первом запуске; `reset_config` стирает его.

## Настройка под сцену

`set tune_mode on` включает отладочный режим. Каждая детекция снимает весь
экран, размечает его и кладёт в буфер последних кадров:

| цвет | что это |
|---|---|
| зелёный | цель, на которую пойдёт курсор |
| жёлтый | прошли `min_blob_area`, но целью не стали |
| серый | отсеяны `min_blob_area` — видно, что режет порог |
| голубой | граница области слежения |

В углу — версия, режим, пороги, координаты цели, число пятен и время реакции.
**F9** пишет буфер на диск, в папку `tune/` с отметкой времени. **Клавиша
остановки в этом режиме не выходит, а ставит паузу** — успеваешь скопировать
нужные кадры; повторное нажатие стирает папку и продолжает.

Режим заведомо медленнее боевого: съёмка всего экрана, отрисовка и
кодирование стоят десятков миллисекунд на кадр.

## Если в игре не наводится

1. `window pick` — выбрать окно игры из списка открытых. Запоминается имя exe,
   потому что заголовок переписывают лаунчеры и моды. `window` покажет, к чему
   привязались и когда это окно видели в последний раз.
2. В логе детекции должно быть `SendInput dx=.. dy=..` с ненулевыми числами.
   Нули — проблема в детекции или прицеле, а не во вводе.
3. Камеру перебрасывает через цель — `set camera_gain 0.3`; доворачивает
   слишком вяло — больше `0.5`.
4. Персонаж крутится без остановки — скрипт читает собственный разворот.
   Увеличь `settle_after_action`, проверь `global_motion_limit`.
5. Автоклик бьёт по воздуху без остановки — подними `click_tolerance`, чтобы
   бить только по наведённой цели.
6. Клавиша слежения конфликтует с игровым биндом (по умолчанию Ctrl, а это
   часто присед) — `set track_key mouse4` или любая свободная клавиша.
